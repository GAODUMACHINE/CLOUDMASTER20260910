## 三、前端契约面（15 调用点）

api.js 12：register / chat / assessment/items / assessment / privacy GET / privacy retention / privacy export / profile DELETE / appeal / resources / report GET / report send
review.js 3：review/pending / review/{id} / review/decision

P5 收口后的契约形态：
- chat/stream 侧请求头 `Authorization: Bearer <profile_key>`（匿名 ID 即凭证），body 只剩 `{"text"}`；
  review 侧令牌改 `Authorization: Bearer <CM_REVIEWER_TOKEN>`（不进 URL/访问日志）。
- api.js 新增 `streamChat`：`fetch + getReader + TextDecoder` 消费 SSE 四事件
  （token 逐段追加 / reply 整段 / held 横幅无动画 / done 终态 + notices 气泡）；
  零事件降级回旧 POST /api/chat 打字机；中途断流保留已到内容不重发；401 不降级。
- 退订开关落地：`reportOptBtn`/`reportOptMsg`（初值 GET /api/report/status/{key}，点击
  unsubscribe/resubscribe）——「随时可退订」承诺不再只有文案。
- review.js 渲染 `followups` 回访待办区（匿名键只显前 8 字符）。
